## :dart: O guia para alavancar a sua carreira

> npm é o gerenciador de pacotes que vem instalado com o Node.js e o coração do ecossistema JavaScript: mais de 3 milhões de pacotes publicados, usados por praticamente todo projeto front-end, back-end ou mobile que você vai encontrar no mercado. Saber usar o npm de verdade — não só `npm install` — significa entender `package.json`, versionamento semântico, scripts, workspaces, auditoria de segurança e como publicar seus próprios pacotes. Este guia reúne documentação oficial, cursos, ferramentas do ecossistema (incluindo alternativas como pnpm e Yarn) e um capítulo dedicado a usar IA na prática com npm — tudo verificado e organizado para quem já roda `node -v` no terminal e quer dominar o gerenciador de pacotes por trás de todo projeto Node.js.

## 🛠️ Ferramentas

> Gerenciadores de pacotes alternativos

- [pnpm](https://pnpm.io/) — Gerenciador que economiza espaço em disco usando links simbólicos; compatível com scripts e registro do npm.
- [Yarn](https://yarnpkg.com/) — Alternativa criada pelo Facebook, com instalação paralela e lockfile próprio.
- [Bun](https://bun.sh/) — Runtime e gerenciador de pacotes extremamente rápido, com CLI compatível com comandos do npm.
- [Volta](https://volta.sh/) — Gerencia versões do Node.js e dos binários de pacotes por projeto, sem precisar de `nvm use` manual.
- [nvm](https://github.com/nvm-sh/nvm) — Gerenciador de versões do Node.js (e, por consequência, da versão do npm que acompanha cada uma).
- [ni](https://github.com/antfu-collective/ni) — Detecta automaticamente se o projeto usa npm, Yarn, pnpm ou Bun e roda o comando certo.

> Manutenção e segurança de dependências

- [npm-check-updates](https://github.com/raineorshine/npm-check-updates) — Verifica e atualiza as versões no `package.json` para as mais recentes, respeitando ranges do semver.
- [npkill](https://github.com/voidcosmos/npkill) — Encontra e remove pastas `node_modules` antigas para liberar espaço em disco.
- [Renovate](https://github.com/renovatebot/renovate) — Bot que abre Pull Requests automáticos de atualização de dependências, com regras configuráveis.
- [Dependabot (documentação oficial)](https://docs.github.com/en/code-security/dependabot) — Recurso nativo do GitHub para alertas e atualizações automáticas de dependências vulneráveis.
- [Snyk](https://snyk.io/) — Escaneia dependências npm em busca de vulnerabilidades conhecidas, com integração no CI.
- [lockfile-lint](https://github.com/lirantal/lockfile-lint) — Valida se as URLs e registros dentro do `package-lock.json` são confiáveis.
- [npq](https://github.com/lirantal/npq) — Substitui o `npm install` por uma versão que analisa riscos do pacote antes de instalar.
- [madge](https://github.com/pahen/madge) — Gera grafos visuais de dependências entre módulos e detecta dependências circulares.
- [depcheck](https://github.com/depcheck/depcheck) — Encontra dependências declaradas no `package.json` que não são mais usadas no código.
- [Calculadora de semver do npm](https://semver.npmjs.com/) — Cole um range (`^1.2.3`, `~2.0.0`) e veja visualmente quais versões ele aceita.

> Publicação e versionamento

- [np](https://github.com/sindresorhus/np) — Fluxo de publicação de pacotes mais seguro que o `npm publish` puro (testes, checklist, tags git).
- [Changesets](https://github.com/changesets/changesets) — Gerencia changelogs e versionamento semântico em monorepos com múltiplos pacotes publicados no npm.
- [semantic-release](https://github.com/semantic-release/semantic-release) — Automatiza versionamento e publicação de pacotes a partir de mensagens de commit.
- [Verdaccio](https://verdaccio.org/) — Registro npm privado e leve para hospedar pacotes internos da sua empresa.
- [publint](https://publint.dev/) — Verifica se o `package.json` de um pacote está configurado corretamente antes de publicar.
- [patch-package](https://github.com/ds300/patch-package) — Aplica e preserva correções em dependências do `node_modules` sem precisar de fork.

> Análise de pacotes

- [Bundlephobia](https://bundlephobia.com/) — Mostra o tamanho real que um pacote npm vai adicionar ao seu bundle final.
- [npm trends](https://npmtrends.com/) — Compara popularidade e downloads de pacotes npm ao longo do tempo.

## 🤖 IA na prática

Usar IA com npm funciona melhor quando ela vira uma segunda opinião sobre dependências e configuração — e não uma fonte de verdade sobre o que instalar.

**Para aprender**
- Cole o conteúdo do seu `package.json` e peça para a IA explicar cada dependência: para que serve, se está desatualizada e se existe alternativa mais leve.
- Peça para explicar, linha a linha, a saída de um `npm audit` real do seu projeto: qual vulnerabilidade é séria, qual pode esperar e por quê.
- Peça exemplos comentados de `npm scripts` com hooks de ciclo de vida (`preinstall`, `postinstall`, `prepublishOnly`) para entender quando cada um roda.
- Peça para comparar um range de semver (`^2.1.0` vs `~2.1.0` vs `2.1.0`) com exemplos de quais versões cada um aceitaria instalar.

**Para trabalhar**
- Use [GitHub Copilot](https://github.com/features/copilot), [Cursor](https://cursor.com/) ou [Claude Code](https://code.claude.com/docs/en/overview) para gerar `npm scripts` de build/test/lint, escrever a configuração inicial de um `package.json` para publicação, e revisar o changelog antes de rodar `npm version`.
- Peça para a IA resumir o [dependency graph](https://docs.github.com/en/code-security/supply-chain-security/understanding-your-software-supply-chain/about-the-dependency-graph) ou os alertas do [GitHub Advisory Database](https://github.com/advisories) de um repositório e priorizar quais atualizações de dependência aplicar primeiro.
- Antes de aceitar uma sugestão de código que adiciona uma dependência nova, peça para a IA justificar a escolha frente a alternativas já instaladas no projeto — evita inflar o `node_modules` sem necessidade.

**Limites e boas práticas**
- IA pode **inventar nomes de pacotes** que não existem no registro (alucinação clássica em geração de código). Sempre confira o nome exato em [docs.npmjs.com](https://docs.npmjs.com/) antes de instalar — instalar um pacote com nome parecido ao certo é um vetor real de ataque (typosquatting).
- Não peça para a IA "resolver" um `npm audit` automaticamente sem revisar: `npm audit fix --force` pode subir versões major e quebrar o projeto.
- Nunca cole tokens do `.npmrc`, chaves de registro privado ou segredos de CI em ferramentas de IA sem a política da sua empresa.
- A decisão final sobre qual dependência entra no projeto é sua: popularidade, manutenção ativa e licença importam mais do que a sugestão mais rápida.

## 🎓 Certificações

Não existe certificação oficial do npm — nem da própria equipe que mantém o registro (hoje parte do GitHub). A certificação mais próxima do tema, a JSNAD (Node.js Application Developer, da OpenJS Foundation/Linux Foundation), foi descontinuada. Na prática, empregadores avaliam **projetos publicados e domínio prático** do gerenciador de pacotes.
- [React: publicando pacotes no npm com versionamento semântico (Alura) — com certificado](https://www.alura.com.br/curso-online-react-publicando-pacotes-npm-versionamento-semantico) — Emite certificado de conclusão para assinantes. Curso pago.
